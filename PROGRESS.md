## Як перевірити зранку

```bash
cp .env.example .env    # впишіть ключі, які маєте; без них усе працює у fake-режимі
docker compose up --build
# http://localhost:8080 → реєстрація → тема → «Надіслати зараз» → «Історія дайджестів»
```

## Що зроблено (по кроках)

1. Скелет: `docker-compose.yml` (mysql 8.4, redis 7, api, worker, bot, web/nginx), healthchecks, `depends_on: service_healthy`, міграції при старті `api`.
2. Backend: моделі SQLAlchemy 2 (async, asyncmy), Alembic-міграція (згенерована на MySQL), argon2, JWT у httpOnly cookie, CSRF (double-submit), rate limit через Redis.
3. Дизайн-система: кремовий фон, теракотовий акцент, Newsreader/Inter/JetBrains Mono, токени в CSS-змінних, темна тема (система + перемикач), login/register, захищені маршрути.
4. CRUD тем + `LLMClient` (OpenAI Responses API + Structured Outputs, ретрай → fallback), ліміт 10 тем, ізоляція користувачів (тести на кожен ендпоінт).
5. Збирачі Google News RSS і Tavily з тестами на записаних фікстурах (без мережі).
6. Embeddings (fastembed, `paraphrase-multilingual-MiniLM-L12-v2`), фільтр релевантності, complete-linkage кластеризація; **пороги відкалібровані на реальній моделі** (див. DECISIONS.md).
7. Пайплайн `process_topic`, рендер Markdown + Telegram HTML (екранування, розбиття ≤4096), fake-провайдери, обробка «бот заблокований».
8. arq cron (5 хв), ідемпотентні job-и, Redis-лок на тему, слоти з урахуванням timezone і DST (13 параметризованих тестів).
9. aiogram-бот: `/start <token>`, `/start`, `/topics`, `/pause`, `/resume` з інлайн-кнопками.
10. Дашборд, редактор теми із запитами, історія з розгортанням, налаштування, polling статусу Telegram кожні 3 с.
11. `scripts/smoke_test.sh`.
12. README з архітектурною схемою (Mermaid), інструкціями щодо ключів і обмеженнями.

## Проблеми, з якими стикнувся, і як вирішено

- **Посеред роботи змінилося ТЗ** (LLM-провайдер Anthropic → OpenAI). Переключився до написання LLM-коду, тож переробляти нічого не довелося.
- **OpenAI SDK 3.x використовує `httpx2`, а не `httpx`**, тому `respx` не перехоплював запити (одна перевірка з фейковим ключем пішла на api.openai.com і отримала 401). Тепер у клієнт передається `http_client` з `httpx2.MockTransport`, і тест перевіряє реальну форму запиту (`/v1/responses`, strict `json_schema`, без tools).
- **Пороги зі ТЗ не підійшли моделі:** схожість заголовка з довгим описом теми — лише 0.19–0.51 (поріг 0.38 відсік би більшість релевантного). Рішення: релевантність = максимум схожості з [описом + пошуковими запитами], поріг 0.30 (чітке розділення 0.26 / 0.32). Очевидні дублікати однієї події дають 0.74–0.85, тож кластерний поріг 0.80 замість 0.85.
- **`redis.lock` у тестах не працює** (fakeredis без Lua) → простий `SET NX EX` з токеном.
- **Після реєстрації користувача перекидало на `/` замість `/topics/new`**: гонка між `RedirectIfAuthed` і навігацією форми. Знайшов браузерним E2E-сценарієм. Виправлено (рішення приймається один раз, на вході на сторінку), додано регресійний тест.
- **bash 3.2 на macOS** псував екрановані лапки всередині `"$(...)"` у smoke-скрипті → JSON-тіла винесено у змінні.
- **Popup-блокери** блокують `window.open` після асинхронного запиту → вкладка відкривається синхронно в обробнику кліку.
- **Мобільна верстка** редактора запитів розвалювалась у стовпчик → grid-розкладка (знайдено на скриншотах).

## Що не перевірено / обмеження

- **Живий Telegram-бот і живий OpenAI не перевірялись**, бо ключів немає. Код покритий тестами з мок-транспортами. Назви моделей `gpt-6-luna` / `gpt-6.1-sol` взято з ТЗ без перевірки; якщо API їх не знає, змініть `LLM_MODEL_*` у `.env` (дайджест тоді все одно прийде через екстрактивний fallback, а помилка буде видна в історії).
- Живий Tavily теж не перевірявся (тільки фікстури й мок SDK).
- Інші обмеження MVP описані в README («Відомі обмеження»).
- `PROMPT_newsdigest_mvp.md` не закомічений: це ваш файл, тож вирішуйте самі.
